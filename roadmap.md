# Roadmap

Phased build plan for the kdb+/q vs Python market microstructure project. Written for Claude Code to execute phase by phase. Check off tasks as completed, update `progress.md` at the end of each phase, and commit/push to GitHub before moving to the next phase (see Git workflow at the bottom).

**Read `progress.md` first** for current status, environment details, data schema, and the full decisions log before starting any phase.

---

## Scope guardrails (do not deviate without asking)

- **In scope**: asof join, OHLC bars, VWAP, spread metrics, trade classification. In both Python and q. Plus a benchmark comparing the two.
- **Out of scope**: PyKX bridge, ML/model integration, synthetic data generation. These were explicitly cut, see `progress.md` decisions log for why.
- **Data**: only the real LOBSTER-derived files (`all_trades.csv`, `all_quotes.csv`). No new data sources without explicit sign-off.
- **Build order matters**: Python must be built and validated first. Do not start the q port until the Python side is confirmed correct.

## Phase 1: Python reference implementation

Build against `data/all_trades.csv` and `data/all_quotes.csv`. This becomes the source of truth the q port is checked against, so correctness here matters more than speed.

- [ ] Load both CSVs, parse `time` as datetime, sort by `time`.
- [ ] **Asof join**: `pd.merge_asof(trades, quotes, on="time", by="sym", direction="backward")`. Confirm zero (or explainably few) unmatched trades, this was already validated at 0 during planning, so a regression here means a bug.
- [ ] **OHLC bars**: `groupby("sym").resample("5min")` on price/size, producing open/high/low/close/volume.
- [ ] **VWAP**: `(price * size).sum() / size.sum()`, grouped by symbol.
- [ ] **Spread metrics**: `midpoint = (bid+ask)/2`, `quotedSpread = ask-bid`, `effectiveSpread = 2*abs(price-midpoint)`.
- [ ] **Trade classification**: classify each trade as buyer- or seller-initiated (e.g., price vs. midpoint). Compare output against the ground-truth `side` column already present in `all_trades.csv` (derived from LOBSTER's direction field) and report agreement rate.
- [ ] Sanity-check outputs against the known validation results from planning (e.g., AAPL opened ~$585.74 that morning).
- [ ] Commit and push. Suggested message: `feat: python reference implementation (asof join, OHLC, VWAP, spreads, classification)`.

## Phase 2: q/kdb+ port

Port Phase 1's logic into idiomatic q. **Not a line-by-line translation** — use q's native tools (`aj`, `xbar`, `wavg`, vectorized functional forms) rather than mimicking pandas' structure. A clunky port would make the later benchmark unfair.

- [ ] `schema.q`: define `trade` and `quote` tables, load from the same CSVs in `data/`.
- [ ] **Asof join**: `aj[\`sym\`time; trade; quote]`.
- [ ] **OHLC bars**: `xbar`-based bucketing, same 5-minute windows as the Python version.
- [ ] **VWAP**: `size wavg price`, grouped by `sym`.
- [ ] **Spread metrics**: same formulas as Phase 1, in q syntax.
- [ ] **Trade classification**: same logic as Phase 1, in q.
- [ ] **Row-for-row validation**: compare q output against Python output from Phase 1 for every operation. This is the correctness gate before any benchmarking happens — do not proceed to Phase 3 until outputs match (or differences are understood and explainable, e.g., floating-point rounding).
- [ ] Commit and push. Suggested message: `feat: q port + validated against python reference`.

## Phase 3: Benchmark harness

- [ ] Subsampling: chronological (first N rows) at three tiers — 10k, 100k, full (~1.04M quotes / ~124k trades). No random sampling, no synthetic data (see `progress.md` decisions log).
- [ ] Time each operation (asof join, OHLC, VWAP) separately, at each tier, in both languages:
  - Python: `time.perf_counter()`
  - q: `\t` prefix in console, or `.z.p` timestamps around the query
- [ ] Track peak memory if feasible (`tracemalloc` in Python; optional, don't block on this if it's awkward in q).
- [ ] **Charting**: default to `matplotlib` unless told otherwise (this was an open item at planning time — confirm with the developer before or during this phase if unclear). One chart per operation, row count on x-axis, time on y-axis (log scale is fine), one line per language.
- [ ] Save charts to `results/`.
- [ ] Note caveats directly in code comments or a short markdown note: in-memory only (not testing kdb+'s on-disk historical engine), chronological subsampling means 10k/100k tiers skew toward the market-open period, idiomatic-not-literal q port.
- [ ] Commit and push. Suggested message: `feat: benchmark harness + results`.

## Git workflow notes

- Commit at the end of each phase, not mid-phase, each commit should represent a working state.
- Push after each commit so progress is visible on GitHub as phases complete.
- Update `progress.md`'s "Current status" line and "Not yet started" list after every phase, this file is the running source of truth for where the project stands.
- If a phase surfaces a decision not already covered in `progress.md`'s decisions log (e.g., a q syntax choice, a validation tolerance), log it there before moving on, don't let undocumented decisions pile up.
